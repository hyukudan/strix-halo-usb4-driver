# DMA progress, exclusive idle reset and quarantine reaping

Patch 0006 follows the source in `main` at
`e351a7c90481ea2c477bb755945afd7392fed15d`. It is a source implementation, not
hardware qualification. No Actions, installation, module reload, firmware write
or controller reset was executed to produce this change.

**Rebuild the complete matching kernel/module set.** The internal `tb_nhi`
structure changes; do not load this stream module alongside an old Thunderbolt
core, USB4NET or other consumers compiled with a different header.

## Progress and event ordering

The mandatory DMA-progress mutex is separate from the ioctl/control-plane mutex.
After fence and reservation-storage allocation, publication rechecks admission
under `dma_lock` and holds it through the complete descriptor enqueue. STOP
cannot interleave between publishing an unsignalled fence and enqueueing its
frames. A timeout occurring during allocation makes the subsequent publication
fail without adding a fence or descriptor.

The watchdog runs on a separate per-context `WQ_UNBOUND | WQ_MEM_RECLAIM` queue.
It never takes `sdev->lock`, accesses user memory, waits on a DMA reservation or
manages paths. It stops the two local DMA rings and joins their callbacks.
Thunderbolt ring completion, cancellation and MSI dispatch use another
reclaim-capable queue, avoiding a watchdog waiting for work on its own queue.
Signalling sections are annotated with `dma_fence_begin_signalling()` and
`dma_fence_end_signalling()`; no potentially reclaiming allocations occur in
the mandatory completion path. This does not provide a hard real-time deadline
or justify signalling memory that hardware might still own.

Local DMA stop and control-plane path removal are distinct. A watchdog stop
retains path identities; explicit STOP, RECOVER or close performs path teardown
after joining DMA. Failure to prove DMA quiescence keeps the fences/mappings
retained. Zero counters or a stopped flag alone do not replace callback joins.

A final callback now transitions through FINISHING. EVENT/POLL readiness is
published only after its fence has been signalled. FINISHING operations cannot
be retired or prepared again. Exporting their sync_file is permitted: the
exported fence can still be unsignalled. This closes the former event/fence
ordering window rather than merely reducing its probability.

## Explicit controller reset

`SGU_IOC_RESET` uses `struct sgu_action`; all operation and output fields must be
zero and the imported identity must match. It requires `CAP_SYS_ADMIN` and a
previous successful STOP. It does not silently stop active traffic to satisfy
a reset request. If any condition fails, imports remain retained.

The core helper `tb_domain_reset_dma()`:

* accepts only the AMD device families enumerated by the pinned upstream
  reset-on-teardown workaround, and only a supported NHI-v1 interface;
* holds a runtime-PM reference and the domain mutex, checks presence, and closes
  allocation/start admission under `nhi->lock` before touching reset state;
* permits only the caller's stopped, empty data rings, plus the control rings;
  **any other allocated data ring, even idle, returns EBUSY**;
* stops the control channel, writes the NHI-v1 interface-reset register at
  0x39858, observes the upstream tHIReset delay, checks presence/capabilities and
  restarts/checks the control rings;
* keeps admission closed if the post-reset hardware or control-channel state
  cannot be established. It returns an error, not a fictional recovery.

Successful RESET releases this session's imported windows and requires a
strictly newer peer-agreed connection epoch before a new IMPORT/ARM. It returns
`SGU_RESULT_CONTROLLER_RESET` and the unimported identity. The peer must also be
quiesced and coordinated by the application.

This is **not** an unconditional reset-on-close, PCI function reset, host-router
reset, PHY retrain, or a mechanism to evict USB4NET/sibling streams. The public
capability means the software interface exists; unsupported hardware still
returns EOPNOTSUPP. Reset is never invoked automatically by the watchdog.

## Administrative quarantine reaping

GPU-mode ConfigFS devices gain:

* `gpu_quarantine`: read-only 0/1 status;
* `gpu_recover`: write `reap` to retry safe cleanup, or `reset` for cleanup plus
  the explicit exclusive idle-controller reset.

The operation requires administrator capability, zero open users, and the same
live endpoint. A context must actually be quarantined. It retries local stop and
path removal, joins callbacks and releases only after all lifetime conditions
are met. Successful cleanup balances the extra device/module quarantine pins.
With no context, `reset` can reset a completely idle supported controller;
`reap` has no context to release and returns ENOENT.

A removed, disconnected or unprovably stopped controller is deliberately **not**
reclaimed. This patch does not implement a generic hot-remove DMA revocation
framework, and such quarantines can still remain retained. A timer cannot prove
that freeing DMA memory is safe. This limitation must not be described as fixed.

Removing a ConfigFS GPU device now stops its DMA context under its device mutex
before marking the group removed. It does not silently rebind retained windows
to a newly discovered peer.

## Read-only statistics

`SGU_IOC_STATS` accepts the exact QUERY identity and zeroes in all remaining
input bytes. It snapshots per-open-context counters: submitted/completed DMA
batches by direction, successful payload bytes, errors, last/maximum DMA
latency, dependency retries, timeouts, stops, explicit reset outcomes and
current/peak pending callbacks. These counters survive session reimport within
the same open context and are reset by a new open context.

The counters describe local controller work. A physical legacy RX_REPOST is a
submission; adopting that standby for a new operation is not another physical
submission. Successful bytes exclude failed/cancelled operations and terminal
metadata. They are **not** remote acknowledgements, payload-integrity results,
GPU cache-visibility proofs or a benchmark claiming a throughput improvement.

## Reconstructing the source

The original capture, original patch 0001 and original source manifest are not
modified. Patch 0004 has been regenerated with ordinary trailing context so
`git apply` does not misinterpret its old context-free-ending hunks as EOF.
Patch 0005's leading-space diff header is normalized. Their intended resulting

`d48623fda79ba43fe1c90d3e37e2cccf43e620ea`, recorded separately in
`provenance/recovery-base.json`. The materializer verifies the additional base,
rejects tampering, duplicate/extra paths and symlinks, and never overwrites a
captured file. The base header is for materialization; do not copy it over an
already patched kernel header after applying the series.

Apply all entries in `patches/series` to the pinned kernel, or materialize with
`python3 tools/prepare_overlay.py audited-overlay`. Raw `overlay/` remains the
original capture and does not include the fixes.

## Validation actually performed for this delivery

28 selected tests passed with GCC and again with Clang. The C simulator tests
use ASan/UBSan and leak detection. They include the original 11 GPU suites,
six new GPU suites (blocked-ioctl/reservation progress, fence/event ordering,
STOP during publication allocation, quarantine fault/retry/refcount handling,
explicit reset lifecycle, stats), five reset-backend suites with MMIO/PCI/PM
doubles, five additional-base tests and one legacy ABI comparison.

The original GPU suite includes 16 simultaneous operations and 2,048 slot-reuse
operations. New pthread interleavings use bounded joins; they are not a complete
exploration of the kernel scheduler. An existing source-guard test is migrated
to the new DMA-stop helper without dropping its stop/callback-accounting checks.

Ordinary patch checks and byte equivalence were run on the complete GPU/logic/
UAPI files and the exact upstream public header. Core integration hunks were
checked against their retrieved source contexts. **The full captured repository,
all pre-existing tests, and the full six-patch pinned-kernel reconstruction were
not run locally in this session.** The supplied installer validates the complete
materializer and repository tests in a disposable local worktree before applying
anything to the requested checkout; it performs no push or Actions call.

Two compile-only compatibility probes against installed Linux 6.12.107 headers
passed with W=1 and -Werror: GPU implementation and reset implementation. They
use stand-ins for private stream/control declarations, newer header placement
and PCI-ID names. They are not a build against 7.3-rc5, not module linking/modpost,
and not proof of kernel/hardware execution. Probe logs and stubs accompany the
delivery so these limits are inspectable.
